# DealChecker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a tested local price monitor with genuine discovery and documented coverage.
**Architecture:** One FastAPI process, SQLite, bounded asyncio scheduler, guarded source adapters and static UI.
**Tech Stack:** Python 3.11+, FastAPI/uvicorn, aiohttp, pytest, plain JS/CSS.
**Spec:** docs/superpowers/specs/2026-11-08-mvp-design.md and docs/project-brief.md.

## Global Constraints
- Only Yuugel/DealChecker; no paid services or secrets in Git.
- Windows 11 local operation; bind 127.0.0.1; Linux portability.
- EUR integer cents; unknown shipping/availability and stale data explicit.
- Priority intervals 300/900/1800/3600 seconds; rate limits apply to manual checks too.
- Reproducible fixtures never presented as real offers.
- Isolated worker branches; lead reviews integrations. User authorized autonomous execution and PR delivery.

## Review Focus
1. Private-address URLs, redirects and DNS rebinding cannot reach local services.
2. Restart and overlapping manual/timed checks cannot duplicate observations or alerts.
3. Unknown shipping, different variants and first observations cannot fabricate savings.
4. Source exceptions and notification failures cannot stop other watches.
5. Stored text cannot inject HTML; hostile origins cannot mutate the local application.
